# 点积

## 为什么需要它

学完向量以后，你已经知道模型把信息表示成高维空间中的点和方向。下一步的问题是：

> **两个向量“有多像”或者“方向有多一致”，怎样变成一个可以计算的数字？**

点积就是最基础的答案之一。

它把两个向量之间的关系压缩成一个标量。这个标量会同时受到**长度**和**夹角**影响，因此它可以从三个角度理解：

- 分量相乘后求和；
- 一个向量在另一个向量方向上的投影；
- 两个方向对齐程度的度量。

<Aside kind="context" title="前置知识">

需要先理解向量、向量长度，以及“方向”这个几何直觉。不会三角函数推导也没关系，本章只需要使用 cosine。

</Aside>

## 从分量计算

对于两个二维向量：

<Equation label="二维点积">

**a · b = aₓbₓ + aᵧbᵧ**

</Equation>

例如：

<Equation>

**[3, 2] · [4, 1] = 3×4 + 2×1 = 14**

</Equation>

这个定义看起来只是“对应分量相乘再相加”，但真正重要的是它背后的几何意义。

<Aside kind="definition" title="为什么结果是一个数">

向量输入，标量输出。点积不是生成一个新方向，而是在回答一个关系问题：这两个向量在多大程度上沿着同一个方向贡献？

</Aside>

## 几何直觉

点积还有一个完全等价的表达：

<Equation label="几何形式">

**a · b = ‖a‖ ‖b‖ cos θ**

</Equation>

其中：

- `‖a‖` 是 a 的长度；
- `‖b‖` 是 b 的长度；
- `θ` 是两个向量之间的夹角。

这条公式把点积的三个因素拆开了：**a 有多长、b 有多长、它们方向有多一致。**

### 符号告诉你方向关系

如果两个向量同向，`cos θ > 0`，所以点积为正。

如果两个向量垂直，`cos 90° = 0`，所以点积为 0。

如果两个向量反向，`cos θ < 0`，所以点积为负。

<Aside kind="tip" title="先看符号，再看大小">

判断一个点积时，可以先问“正、零、负”，再问“有多大”。这比一上来计算分量更容易建立几何直觉。

</Aside>

## 投影视角

把几何形式稍微重排：

<Equation label="a 在 b 方向上的投影长度">

**proj_b(a) = (a · b) / ‖b‖**

</Equation>

这告诉我们：点积可以理解为“a 沿着 b 方向到底贡献了多少”，再乘上 b 自己的长度。

因此点积不只是一个相似度公式，它也是**投影**的核心。

## 从点积到余弦相似度

将几何形式两边同时除以两个向量长度：

<Equation label="Cosine similarity">

**cos θ = (a · b) / (‖a‖ ‖b‖)**

</Equation>

这样得到的值被限制在 `[-1, 1]`：

- `1`：完全同向；
- `0`：正交；
- `-1`：完全反向。

<Aside kind="derivation" title="归一化的本质">

如果先把 a 和 b 都缩放成长度为 1 的单位向量，那么它们的点积就直接等于 cosine similarity。

所以“先 normalize，再 dot product”是机器学习里非常常见的模式。

</Aside>

## 最小实现

<CodeStep title="dot-product.ts">

~~~ts
type Vector = number[];

function dot(a: Vector, b: Vector): number {
  if (a.length !== b.length) {
    throw new Error("vectors must have the same dimension");
  }

  return a.reduce((sum, value, index) => {
    return sum + value * b[index]!;
  }, 0);
}

function magnitude(v: Vector): number {
  return Math.sqrt(dot(v, v));
}

function cosineSimilarity(a: Vector, b: Vector): number {
  const denominator = magnitude(a) * magnitude(b);

  if (denominator === 0) {
    return 0;
  }

  return dot(a, b) / denominator;
}
~~~

</CodeStep>

这里最值得注意的一行是：

`magnitude(v) = sqrt(dot(v, v))`

向量长度本身，也可以从点积定义出来。

## 与 Attention 的关系

Transformer 中最重要的 Attention score 之一，本质上就是 Query 和 Key 的点积：

<Equation label="Scaled dot-product attention score">

**score(q, k) = (q · k) / √d**

</Equation>

模型会问：

> 当前 Query 与某个 Key 的方向关系有多强？

点积越大，通常意味着这个 Key 与当前 Query 更匹配。

再经过 scaling 和 Softmax，这些 score 会变成 Attention weights。

<Aside kind="source" title="为什么还要除以 √d">

维度越高，未归一化点积的数值尺度通常越大。Scaled Dot-Product Attention 用 `√d` 缩放 score，避免 Softmax 过早进入非常尖锐的区域。我们会在 Attention 章节完整推导。

</Aside>

## 与 Agent 的关系

点积在 Agent 系统中最直接的两个入口是：

### Embedding retrieval

RAG 或 semantic memory 会把查询和文档表示成 embedding vector。

检索系统需要判断：

> 哪些文档向量与 query vector 最接近？

常见做法就是 cosine similarity，或者对归一化后的 embedding 直接做点积。

### Attention

Agent 的 prompt、tool result、memory 最终都进入模型 context。Transformer 内部需要不断决定：

> 当前 token 应该从哪些位置读取更多信息？

这个关系判断的核心之一仍然是点积。

所以你可以把点积理解成一个非常基础的“**相关性压缩器**”：

> **两个高维方向进去，一个关系强度出来。**
