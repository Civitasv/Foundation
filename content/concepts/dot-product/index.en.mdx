# Dot Product

## Why it exists

After vectors, the next question is:

> **How do we turn “these two vectors point in similar directions” into one computable number?**

The dot product is one of the most fundamental answers.

It compresses the relationship between two vectors into a scalar. That scalar depends on both **magnitude** and **angle**, so the dot product has three useful interpretations:

- multiply corresponding components and sum them;
- measure projection along another vector;
- measure directional alignment.

<Aside kind="context" title="Prerequisites">

You should already understand vectors, vector magnitude, and the geometric idea of direction. You do not need to derive trigonometric identities in this chapter.

</Aside>

## Component form

For two 2D vectors:

<Equation label="2D dot product">

**a · b = aₓbₓ + aᵧbᵧ**

</Equation>

For example:

<Equation>

**[3, 2] · [4, 1] = 3×4 + 2×1 = 14**

</Equation>

The definition looks like “multiply matching components and add,” but the geometric interpretation is what makes it powerful.

<Aside kind="definition" title="Why the result is a scalar">

Vectors go in; one number comes out. The dot product does not create a new direction. It answers a relationship question: how strongly do these vectors contribute along the same direction?

</Aside>

## Geometric intuition

The same operation can be written as:

<Equation label="Geometric form">

**a · b = ‖a‖ ‖b‖ cos θ**

</Equation>

where:

- `‖a‖` is the magnitude of a;
- `‖b‖` is the magnitude of b;
- `θ` is the angle between them.

This separates the three ingredients: **how long a is, how long b is, and how aligned their directions are.**

### The sign tells you the relationship

Same direction gives `cos θ > 0`, so the dot product is positive.

Perpendicular vectors give `cos 90° = 0`, so the dot product is zero.

Opposite directions give `cos θ < 0`, so the dot product is negative.

<Aside kind="tip" title="Read the sign before the magnitude">

When reasoning about a dot product, first ask whether it should be positive, zero, or negative. Only then ask how large it should be.

</Aside>

## Projection view

Rearrange the geometric form:

<Equation label="Length of a projected onto b">

**proj_b(a) = (a · b) / ‖b‖**

</Equation>

This says the dot product can measure how much of a lies along the direction of b, scaled by the magnitude of b.

So the dot product is not only a similarity formula. It is also the core of projection.

## From dot product to cosine similarity

Divide the geometric form by both magnitudes:

<Equation label="Cosine similarity">

**cos θ = (a · b) / (‖a‖ ‖b‖)**

</Equation>

The result lies in `[-1, 1]`:

- `1`: same direction;
- `0`: orthogonal;
- `-1`: opposite direction.

<Aside kind="derivation" title="What normalization does">

If a and b are both normalized to unit length first, their dot product is exactly cosine similarity.

That is why “normalize, then dot” is such a common machine-learning pattern.

</Aside>

## Minimal implementation

<CodeStep title="dot-product.ts">

~~~ts
type Vector = number[];

function dot(a: Vector, b: Vector): number {
  if (a.length !== b.length) {
    throw new Error("vectors must have the same dimension");
  }

  return a.reduce((sum, value, index) => {
    return sum + value * b[index]!;
  }, 0);
}

function magnitude(v: Vector): number {
  return Math.sqrt(dot(v, v));
}

function cosineSimilarity(a: Vector, b: Vector): number {
  const denominator = magnitude(a) * magnitude(b);

  if (denominator === 0) {
    return 0;
  }

  return dot(a, b) / denominator;
}
~~~

</CodeStep>

The interesting identity is:

`magnitude(v) = sqrt(dot(v, v))`

Vector length itself can be defined using the dot product.

## Connection to Attention

One of the most important Transformer attention scores is literally a Query–Key dot product:

<Equation label="Scaled dot-product attention score">

**score(q, k) = (q · k) / √d**

</Equation>

The model is asking:

> How strongly does this Key align with the current Query?

A larger dot product usually means a stronger match.

After scaling and Softmax, these scores become attention weights.

<Aside kind="source" title="Why divide by √d">

In higher dimensions, unnormalized dot products tend to have larger numerical scale. Scaled Dot-Product Attention divides by `√d` to keep Softmax from becoming too sharp too early. We will derive this fully in the Attention chapter.

</Aside>

## Connection to Agent engineering

The dot product appears in Agent systems through at least two direct paths.

### Embedding retrieval

RAG and semantic memory represent queries and documents as embedding vectors.

The retrieval system needs to answer:

> Which document vectors are closest to the query vector?

A common answer is cosine similarity, or a direct dot product after normalization.

### Attention

An Agent's prompt, tool results, and memory all enter model context. Inside the Transformer, the model repeatedly decides:

> Which positions should the current token read from more strongly?

Dot products are one of the core operations behind that relationship score.

A useful mental model is:

> **Two high-dimensional directions go in; one relationship strength comes out.**
