# 矩阵

## 摘要

矩阵既能记录一批数据，也能在选定基底后表示一个线性变换。理解这两种角色，是阅读神经网络公式的重要准备。本章从基向量的去向推导矩阵乘法，用二维实例讨论行列式、秩与可逆性，再将变换的复合推广到批量表示和 Transformer 中的计算。几何图像、逐项计算与模型用法会相互对照，尤其关注维度约定和信息保留，避免把所有矩阵运算都笼统地称为“投影”。

## 从一组表示到一种变换

向量一章讨论了怎样用坐标表示对象。接下来的问题是：如果希望改变表示，该怎样写出这种改变？例如，把平面上每个点的横坐标放大一倍，或者把一个三维特征向量转换成两个评分，都需要一套同时适用于许多输入的规则。

矩阵可以记录这样的规则。写成 `y = Ax` 时，x 是输入，A 描述变换，y 是输出。但矩阵也可能只是数据的排列：一份表格的每一行记录一个样本，一个模型输入矩阵的每一行记录一个 token。相同的二维数组形式，在公式里可以扮演不同角色。先辨认它代表数据还是参数，再检查它怎样参与运算，通常比只盯着乘法符号更有用。

<Aside kind="context" title="阅读准备">

本章以前面的[向量](/concepts/vector/)、向量加法和标量乘法为起点。二维部分采用列向量约定。点积会在解释逐项计算时出现，但推导可以直接从线性组合出发。

</Aside>

## 线性变换怎样决定矩阵的列

### 线性保留了哪些关系

一个线性变换 T 满足：

<Equation label="线性的两个条件">

**T(u + v) = T(u) + T(v)**

**T(αv) = αT(v)**

</Equation>

这两个条件允许我们先把输入拆成容易处理的部分，分别变换，再按原来的系数组合结果。它们也意味着 `T(0) = 0`。所以绕原点旋转、沿坐标轴缩放都可以是线性变换，而把平面上每个点向右平移一个单位不满足这一条件。

<Aside kind="definition" title="矩阵与基底">

在有限维空间中，选定输入和输出的基底后，每个线性变换都可以用一个矩阵表示。更换基底时，描述同一个变换的矩阵可能改变。下文使用标准基底，把注意力集中在变换本身。

</Aside>

### 从两根基向量推导乘法

设 `e₁ = [1, 0]ᵀ`、`e₂ = [0, 1]ᵀ`，并希望变换把它们分别送到 `[2, 1]ᵀ` 与 `[-1, 1]ᵀ`。把这两个结果按列排在一起，就得到：

<Equation label="用基向量的像构造矩阵">

**A = [[2, -1], [1, 1]]**

**Ae₁ = [2, 1]ᵀ,　Ae₂ = [-1, 1]ᵀ**

</Equation>

这里每个内层括号表示一行。由于任意 `v = [x, y]ᵀ` 都可以写成 `xe₁ + ye₂`，线性条件给出：

<Equation label="输入坐标决定如何组合矩阵的列">

**Av = xAe₁ + yAe₂ = [2x - y, x + y]ᵀ**

</Equation>

例如 `v = [3, 2]ᵀ`，结果就是 `3[2, 1]ᵀ + 2[-1, 1]ᵀ = [4, 5]ᵀ`。乘法规则在这里有了来源：输入的第一个坐标乘第一列，第二个坐标乘第二列，再把它们相加。

推广到 `A = [[a, b], [c, d]]`，便得到 `Av = [ax + by, cx + dy]ᵀ`。从列看，是在组合变换后的基向量；从行看，每一个输出分量都是一行系数与输入的加权求和。这两个视角描述同一件事，前者便于想象空间怎样变化，后者便于检查每个输出是怎么算出来的。

## 行列式、秩与丢失的信息

### 面积缩放并不等于长度缩放

在二维中，单位正方形的两条边是 e₁、e₂。变换后，它们成为矩阵的两列，围出的平行四边形面积为 `|ad - bc|`。行列式保留了面积与定向的信息：

<Equation label="二维行列式">

**det(A) = ad - bc**

</Equation>

对前面的 `[[2, -1], [1, 1]]`，行列式为 3，因此面积变成原来的三倍。负行列式表示定向发生翻转，绝对值仍是面积缩放倍数。`[[-1, 0], [0, 1]]` 的行列式是 -1，面积不变，但平面的定向翻转了。

行列式只给出整体的面积关系。`[[2, 0], [0, 0.5]]` 的行列式为 1，却把横向拉长、纵向压短。因而，面积不变并不意味着长度或夹角不变，也不能据此断定这是旋转。

### 不同输入为什么会变成同一个输出

考虑 `P = [[1, 0], [0, 0]]`。它把 `[x, y]ᵀ` 变成 `[x, 0]ᵀ`，所以 `[2, 1]ᵀ` 与 `[2, 7]ᵀ` 都得到 `[2, 0]ᵀ`。只看输出，就没有办法知道原来的第二个坐标。这就是不可逆的信息丢失。

矩阵的秩是其列所张成空间的维数。P 的两列只能张成横轴，因此秩为 1；零矩阵的秩为 0；两列线性无关的二维方阵则有秩 2。对于方阵，行列式不为零、满秩与可逆是等价条件。

<Aside kind="derivation" title="零空间说明哪些差异消失了">

所有被映射到零向量的输入组成零空间。若 `Az = 0`，那么 `A(v + z) = Av`：相差 z 的两个输入产生相同输出。对 P 而言，所有形如 `[0, y]ᵀ` 的向量都在零空间中，所以纵向差异完全丢失。

</Aside>

神经网络经常使用非方阵，这时没有普通的行列式可算，但秩仍然有意义。把三维空间线性映射到二维，秩最多为 2，必然有某些输入差异无法保留；反过来，把二维映射到三维，输出虽有三个坐标，可达的表示仍至多占据一个二维子空间。增加坐标数量本身并不创造新的独立信息。

这类压缩未必是坏事。如果任务只关心 x，那么丢弃 y 可能恰好符合需求。工程中真正要判断的是，丢掉的区别是否仍被后续任务需要。

## 复合变换为什么有顺序

如果先做 A，再做 B，列向量经历的是 `v → Av → B(Av)`。我们把两次作用写成一个矩阵：

<Equation label="矩阵乘法表示复合">

**B(Av) = (BA)v**

</Equation>

BA 的第 j 列，就是 B 作用于 A 的第 j 列所得的结果。因为 A 的第 j 列记录了第 j 根基向量第一步去了哪里，再让 B 处理它，就记录了两步之后的去向。这也推导出了熟悉的“行乘列”算法：BA 的每个元素，都是 B 的一行与 A 的一列逐项相乘后求和。

顺序可以用一个很小的例子检验。设 S 把横坐标放大两倍，R 绕原点逆时针旋转 90°：

<Equation label="先缩放与先旋转得到不同结果">

**S = [[2, 0], [0, 1]],　R = [[0, -1], [1, 0]]**

**RS[1, 0]ᵀ = [0, 2]ᵀ**

**SR[1, 0]ᵀ = [0, 1]ᵀ**

</Equation>

差异来自缩放作用的方向。先旋转后，原来的横向向量已经落到纵轴上，S 就不会再把它拉长。因此矩阵乘法一般不满足交换律，但满足结合律，`C(BA) = (CB)A`，只要各维度匹配。

这一性质也解释了神经网络为什么需要非线性。如果若干层只做线性变换，它们总能合并成一个矩阵；即使加入偏置，若没有其他非线性操作，复合后仍是一个仿射变换。层与层之间的非线性使网络能够超出这一限制。

## 数据矩阵与批量计算

到这里一直使用列向量。若 A 有 m 行、d 列，就把 d 维输入映射为 m 维输出。模型实现中也常把一批输入按行存放。例如，n 个 token 的 d 维表示组成 X，再乘一个 d 行、k 列的权重矩阵 W：

<Equation label="批量表示的维度">

**X ∈ ℝⁿˣᵈ,　W ∈ ℝᵈˣᵏ**

**Y = XW ∈ ℝⁿˣᵏ**

</Equation>

中间的 d 对应参与求和的特征维度；结果保留 n 个 token，每个 token 得到 k 个输出分量。这里 X 承载数据，W 承载共享的变换参数。单独这一步不会把不同 token 混合起来，因为每一行都使用同一个 W 独立变换。

一个小例子是 `X = [[1, 2], [3, 4]]`，`W = [[2], [-1]]`。第一行给出 `1×2 + 2×(-1) = 0`，第二行给出 `3×2 + 4×(-1) = 2`，所以输出是 `[[0], [2]]`。相同规则被应用了两次。

<Aside kind="definition" title="行向量与列向量的对应关系">

若列向量写作 `y = Ax`，转置后便有 `yᵀ = xᵀAᵀ`。因此同一个变换在行向量约定下使用 `W = Aᵀ`，并不是把同一个矩阵原样移到右侧。转置会交换行列：A 为 m×d 时，Aᵀ 为 d×m。

</Aside>

常见的神经网络线性层还带有偏置，写成 `y = Ax + b`。严格说它是仿射变换：A 先改变表示，b 再平移结果；当 b 非零时，原点不再保持不动。“线性层”是常用名称，读推导时仍要区分是否包含这一项。

## 最小实现与输入约定

下面的实现依次给出矩阵乘向量、转置和矩阵乘矩阵。它假定所有矩阵非空、各行等长，元素是有限实数，而且相乘的维度匹配。代码中的 `!` 只向 TypeScript 声明索引存在，不会替程序执行这些检查。

<CodeStep title="matrix.ts">

~~~ts
type Matrix = number[][];
type Vector = number[];

function matVec(matrix: Matrix, vector: Vector): Vector {
  return matrix.map((row) =>
    row.reduce((sum, value, index) => sum + value * vector[index]!, 0)
  );
}

function transpose(matrix: Matrix): Matrix {
  return matrix[0]!.map((_, column) =>
    matrix.map((row) => row[column]!)
  );
}

function matMul(a: Matrix, b: Matrix): Matrix {
  const columns = transpose(b);

  return a.map((row) =>
    columns.map((column) =>
      row.reduce((sum, value, index) => sum + value * column[index]!, 0)
    )
  );
}
~~~

</CodeStep>

`matVec([[2, -1], [1, 1]], [3, 2])` 得到 `[4, 5]`。`matMul([[1, 2], [3, 4]], [[2], [-1]])` 得到 `[[0], [2]]`。把上一节的 R 与 S 分别按两种顺序传给 `matMul`，就能检验旋转与缩放的差异。这里反复出现的“对应元素相乘再求和”，就是[点积](/concepts/dot-product/)所讨论的运算。

这段代码展示计算结构，尚未处理不规则数组、维度错误或大规模数值计算的效率。比如一行比预期短时，缺失项可能使结果变成 `NaN`。把它用于实际输入之前，需要校验约定；用于大模型时，则通常由张量库和底层数值计算实现这些运算。

## 在 Transformer 中辨认矩阵的角色

以单个自注意力头为例，输入 X 的各行是 token 表示。三个权重矩阵先生成查询、键和值，再由查询与键的乘积形成位置之间的分数。这是 Transformer 论文中线性代数组织计算的一个具体实例。[Vaswani 等，2017](https://arxiv.org/abs/1706.03762)。

<Equation label="从特征变换到位置比较">

**Q = XW_Q,　K = XW_K,　V = XW_V**

**Q、K 的形状为 n × dₖ，QKᵀ 的形状为 n × n**

</Equation>

这里 dₖ 是查询和键的维度。QKᵀ 的第 i 行、第 j 列记录第 i 个查询与第 j 个键的点积。与 XW 的逐行特征变换相比，这一步开始比较不同位置。分数还需要缩放、按需要添加掩码，再通过 [Softmax](/concepts/softmax/)得到权重；权重矩阵与 V 相乘，才形成跨位置的信息汇总。完整机制见[自注意力](/concepts/self-attention/)。

这些权重矩阵常被称为“投影矩阵”，但通常只是可学习的线性映射。严格的投影需要满足 `P² = P`；正交投影还有更强条件。Q/K/V 的权重并没有普遍受到这样的约束。把“查询是在找什么”作为功能比喻可以帮助入门，具体哪些信息被提取，仍取决于训练。

## 讨论：从算得出到解释得清

几何视角让我们看见矩阵怎样作用于空间，行列计算让我们核对每个输出，维度分析则帮助定位模型代码中的错误。三者应该相互补充。只用二维几何解释高维模型容易过度想象，只按数组计算又容易忽略信息是怎样变换和丢失的。

对 Agent 工程而言，输入的用户请求、工具结果与检索材料会进入模型的表示计算。但某个矩阵形状正确、某层输出维度符合预期，只能证明局部计算满足相应约定，不能证明系统理解了任务或完成了操作。评价仍然需要回到模型输出和工具执行结果。

本章提供了一种读公式的方法：先确定每个矩阵承载什么，再检查它的输入输出空间，最后追踪变换的顺序及其保留的信息。向量、矩阵与点积由此连成一条线；概率分布和 Softmax 则补上权重与选择的部分。沿着这两条线，可以逐步拆开注意力中的计算。
