# Matrix

## Abstract

Matrices can store batches of data or represent linear transformations once bases are chosen. Distinguishing these roles helps make neural-network formulas readable. This chapter derives multiplication from the images of basis vectors, uses two-dimensional examples to examine determinants, rank, and invertibility, then extends composition to batched representations and Transformer computations. Geometry, entry-wise calculation, and model applications are compared throughout, with particular attention to dimensions and information preservation rather than calling every matrix operation a projection.

## From a representation to a transformation

The vector chapter examined how coordinates represent objects. How can we change a representation systematically? Doubling the horizontal coordinate of every point, or converting three input features into two scores, calls for a rule that applies to many inputs.

A matrix can encode that rule. In `y = Ax`, x is the input, A specifies a transformation, and y is the output. But a matrix can also simply arrange data: each row of a table might contain a sample, or each row of a model input might contain a token representation. The same two-dimensional array can play different roles. Identifying data and parameters, then checking their operations, is often more useful than looking at multiplication alone.

<Aside kind="context" title="Reading prerequisites">

This chapter builds on [Vector](/en/concepts/vector/), vector addition, and scalar multiplication. The geometric examples use column vectors. Dot products appear in entry-wise calculations, but the derivation can begin directly with linear combinations.

</Aside>

## How a linear transformation determines matrix columns

### What linearity preserves

A linear transformation T satisfies:

<Equation label="The two conditions of linearity">

**T(u + v) = T(u) + T(v)**

**T(αv) = αT(v)**

</Equation>

These conditions let us decompose an input, transform its pieces, and recombine them with the original coefficients. They also imply `T(0) = 0`. Rotation about the origin and scaling along coordinate axes can be linear; moving every point one unit right cannot.

<Aside kind="definition" title="Matrices and bases">

In finite-dimensional spaces, choosing input and output bases gives each linear transformation a matrix representation. Changing bases can change the matrix describing the same map. We use standard bases here to concentrate on the transformation itself.

</Aside>

### Deriving multiplication from two basis vectors

Let `e₁ = [1, 0]ᵀ` and `e₂ = [0, 1]ᵀ`. Suppose their desired images are `[2, 1]ᵀ` and `[-1, 1]ᵀ`. Place those images in columns:

<Equation label="Constructing a matrix from basis-vector images">

**A = [[2, -1], [1, 1]]**

**Ae₁ = [2, 1]ᵀ,　Ae₂ = [-1, 1]ᵀ**

</Equation>

Each inner pair of brackets denotes a row. Since every `v = [x, y]ᵀ` equals `xe₁ + ye₂`, linearity gives:

<Equation label="Input coordinates combine the columns">

**Av = xAe₁ + yAe₂ = [2x - y, x + y]ᵀ**

</Equation>

For `v = [3, 2]ᵀ`, the result is `3[2, 1]ᵀ + 2[-1, 1]ᵀ = [4, 5]ᵀ`. This gives the multiplication rule its purpose: multiply the first column by the first input coordinate, the second column by the second coordinate, and add.

For a general `A = [[a, b], [c, d]]`, we obtain `Av = [ax + by, cx + dy]ᵀ`. The column view combines transformed basis vectors; the row view calculates each output component as a weighted sum of the input. They describe the same operation. Columns help visualize the space, while rows make individual outputs easy to check.

Rank and determinant describe it numerically.

## Determinant, rank, and lost information

### Area scaling is not length scaling

The unit square has edges e₁ and e₂. After transformation they become the matrix columns, enclosing a parallelogram of area `|ad - bc|`. The determinant records area scaling and orientation:

<Equation label="Two-dimensional determinant">

**det(A) = ad - bc**

</Equation>

For `[[2, -1], [1, 1]]`, the determinant is 3, so areas triple. A negative determinant reverses orientation, while its absolute value still gives the area factor. `[[-1, 0], [0, 1]]` has determinant -1: it preserves area and reverses orientation.

The determinant does not describe every geometric change. `[[2, 0], [0, 0.5]]` has determinant 1 while stretching horizontally and compressing vertically. Preserving area does not imply preserving lengths or angles, and does not identify a rotation.

### Why different inputs can share an output

Consider `P = [[1, 0], [0, 0]]`. It sends `[x, y]ᵀ` to `[x, 0]ᵀ`, so both `[2, 1]ᵀ` and `[2, 7]ᵀ` become `[2, 0]ᵀ`. The output cannot recover the second input coordinate. Information has been irreversibly lost.

A matrix's rank is the dimension spanned by its columns. P spans only the horizontal axis and has rank 1. The zero matrix has rank 0; a two-dimensional square matrix with independent columns has rank 2. For square matrices, a nonzero determinant, full rank, and invertibility are equivalent conditions.

<Aside kind="derivation" title="The null space identifies differences that disappear">

Inputs mapped to zero form the null space. If `Az = 0`, then `A(v + z) = Av`: inputs differing by z have the same output. For P, every `[0, y]ᵀ` lies in the null space, so vertical differences disappear completely.

</Aside>

Neural networks often use rectangular matrices. They have no ordinary determinant, but rank still applies. A linear map from three dimensions to two has rank at most 2 and must lose some input distinctions. In the other direction, mapping two dimensions into three gives outputs with three coordinates, but the reachable representations still occupy at most a two-dimensional subspace. Additional coordinates alone do not create independent information.

Compression can be useful. If a task depends only on x, discarding y may be appropriate. The engineering question is whether the distinctions removed remain necessary for subsequent work.

## Why composition has an order

Applying A and then B takes a column vector through `v → Av → B(Av)`. Matrix multiplication represents the combined action:

<Equation label="Matrix multiplication represents composition">

**B(Av) = (BA)v**

</Equation>

Column j of BA is B applied to column j of A. That column of A records the first destination of basis vector j; applying B records its destination after both steps. This also derives the row-by-column algorithm: each entry of BA sums products of corresponding entries from a row of B and a column of A.

A small example exposes the effect of order. Let S double the horizontal coordinate and R rotate 90° counterclockwise about the origin:

<Equation label="Scaling first and rotating first give different results">

**S = [[2, 0], [0, 1]],　R = [[0, -1], [1, 0]]**

**RS[1, 0]ᵀ = [0, 2]ᵀ**

**SR[1, 0]ᵀ = [0, 1]ᵀ**

</Equation>

The difference comes from the direction in which scaling acts. After rotation, the initially horizontal vector is on the vertical axis, where S does not stretch it. Matrix multiplication is generally noncommutative, though it is associative: `C(BA) = (CB)A` whenever dimensions match.

Composition also explains why neural networks need nonlinear operations. A sequence of purely linear layers combines into one matrix. Adding biases without other nonlinear operations still leaves an affine map after composition. Nonlinearity between layers allows the network to go beyond that restriction.

## Data matrices and batch computation

So far, vectors have been columns. A matrix A with m rows and d columns maps a d-dimensional input to an m-dimensional output. Implementations also commonly store batches of inputs as rows. Let X contain n token representations of dimension d, and W have d rows and k columns:

<Equation label="Dimensions of a batched transformation">

**X ∈ ℝⁿˣᵈ,　W ∈ ℝᵈˣᵏ**

**Y = XW ∈ ℝⁿˣᵏ**

</Equation>

The shared dimension d indexes the features being summed over. The result retains n tokens, each with k output components. X carries data; W carries shared transformation parameters. This operation alone does not mix tokens: each row is transformed independently using the same W.

For example, take `X = [[1, 2], [3, 4]]` and `W = [[2], [-1]]`. The first row produces `1×2 + 2×(-1) = 0`, and the second produces `3×2 + 4×(-1) = 2`. The result is `[[0], [2]]`: the same rule applied twice.

<Aside kind="definition" title="Relating row and column conventions">

Transposing the column-vector expression `y = Ax` gives `yᵀ = xᵀAᵀ`. The same transformation therefore uses `W = Aᵀ` with row vectors; the matrix cannot simply be moved unchanged to the other side. Transposition swaps rows and columns: an m×d matrix becomes d×m.

</Aside>

A neural-network linear layer often includes a bias, `y = Ax + b`. Strictly, this is affine: A transforms the representation and b translates the result. With a nonzero bias, the origin is no longer fixed. “Linear layer” is conventional terminology, but the distinction matters in a derivation.

## Minimal implementation and input assumptions

The implementation gives matrix–vector multiplication, transposition, and matrix–matrix multiplication. It assumes nonempty rectangular matrices containing finite real values and compatible multiplication dimensions. The `!` assertions tell TypeScript that indexed values exist; they do not perform runtime checks.

<CodeStep title="matrix.ts">

~~~ts
type Matrix = number[][];
type Vector = number[];

function matVec(matrix: Matrix, vector: Vector): Vector {
  return matrix.map((row) =>
    row.reduce((sum, value, index) => sum + value * vector[index]!, 0)
  );
}

function transpose(matrix: Matrix): Matrix {
  return matrix[0]!.map((_, column) =>
    matrix.map((row) => row[column]!)
  );
}

function matMul(a: Matrix, b: Matrix): Matrix {
  const columns = transpose(b);

  return a.map((row) =>
    columns.map((column) =>
      row.reduce((sum, value, index) => sum + value * column[index]!, 0)
    )
  );
}
~~~

</CodeStep>

`matVec([[2, -1], [1, 1]], [3, 2])` returns `[4, 5]`. `matMul([[1, 2], [3, 4]], [[2], [-1]])` returns `[[0], [2]]`. Passing R and S to `matMul` in both orders checks the rotation-and-scaling example. The repeated operation of multiplying corresponding values and summing them is the [dot product](/en/concepts/dot-product/).

The code exposes the computation without handling ragged arrays, incompatible dimensions, or large-scale efficiency. A shorter-than-expected row can introduce missing values and produce `NaN`. Real inputs require validation of the assumptions; large models ordinarily delegate these operations to tensor libraries and optimized numerical implementations.

## Identifying matrix roles in a Transformer

Consider one self-attention head. Rows of X hold token representations. Three weight matrices form queries, keys, and values, then a query–key product produces scores between positions. The Transformer paper gives a concrete use of these operations. [Vaswani et al., 2017](https://arxiv.org/abs/1706.03762).

<Equation label="From feature transformations to position comparisons">

**Q = XW_Q,　K = XW_K,　V = XW_V**

**Q, K: n × dₖ;　QKᵀ: n × n**

</Equation>

Here dₖ is the query and key dimension. Entry i,j of QKᵀ is the dot product between query i and key j. Whereas XW transforms features independently within rows, this operation compares positions. Scores still need scaling, any required mask, and [Softmax](/en/concepts/softmax/) to obtain weights. Multiplying those weights by V aggregates information across positions. [Self Attention](/en/concepts/self-attention/) develops the full mechanism.

These learned matrices are often called projections, but usually mean general linear maps. A mathematical projection satisfies `P² = P`; an orthogonal projection has additional conditions. Q/K/V weights are not generally constrained in that way. Describing a query as “what I am looking for” can illustrate its role, but which information the map extracts depends on training.

## Discussion: calculating and interpreting

Geometry shows how matrices act on spaces, entry-wise calculations verify outputs, and dimension analysis helps locate code errors. These views support one another. Two-dimensional pictures can invite excessive interpretation of high-dimensional models, while array arithmetic alone can conceal how information changes or disappears.

For agents, user requests, tool results, and retrieved material enter the model's representation computations. Correct matrix shapes and expected output dimensions establish local computational consistency; they do not establish that the system understood a task or completed an operation. Evaluation still needs model outputs and execution results.

This chapter offers a way to read formulas: identify what each matrix carries, check its input and output spaces, then follow composition and information preservation. Vectors, matrices, and dot products form one connected line of reasoning. Probability distributions and Softmax add weights and selection. Together, they make attention's calculations possible to unpack step by step.
