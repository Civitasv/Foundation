# 章节引言：为什么学习这些基础

## 从会调用模型到能解释它

调用一个模型接口，通常不需要先会矩阵乘法。把问题发出去，拿到回答，再接上几个工具，就可以开始做一个 Agent。那为什么还要停下来学向量、点积和概率？

困难往往出现在结果不符合预期的时候。检索返回了一段措辞相近却答非所问的材料；同一个问题连续问几次，答案有所不同；模型对一个错误答案给出了很高的概率。要判断这些现象，光知道接口怎么调用还不够。我们需要看懂系统里的数值表示什么，经过了哪些运算，以及这些运算能够支持怎样的判断。

“基础”这一章从这里开始。我们会选取后续模型和 Agent 章节反复用到的数学工具，把它们放回具体问题中解释。读者不必先修完整的线性代数或概率论课程；公式会随着问题出现，符号也会在使用时说明。

## 这些概念怎样连在一起

假设要从一组文档中找到与问题相关的段落。一种常见做法是把问题和段落分别编码成向量，再比较它们。这里首先要理解的，就是[向量](/concepts/vector/)：一组坐标怎样承载特征，长度与方向各自表达什么。几何图像能帮助我们形成直觉，但模型里的坐标往往没有逐维可命名的含义。学会区分数值表示和我们赋予它的解释，是阅读模型的第一步。

接着要问，表示怎样发生变化。[矩阵](/concepts/matrix/)把这件事写成可计算的变换。理解矩阵乘向量之后，神经网络中的线性层就有了具体含义：输入的不同分量怎样被组合，输出的维度从哪里来。再看注意力中的查询、键和值时，就能追问它们是如何由输入得到的。

有了表示，还需要比较。[点积](/concepts/dot-product/)把两个向量的关系变成一个数。它会出现在相似度计算和注意力分数中，但这个数同时受方向与长度影响。理解这一点，才知道为什么向量归一化会改变比较方式，也才不会把一个较大的分数直接当作“语义更接近”的充分证据。

[概率分布](/concepts/probability/)处理另一类问题：当多个结果都有可能发生时，怎样描述它们的可能性。语言模型生成下一个 token 时，会面对一组候选结果；采样则从分布中选择一个。学习概率、期望与熵，可以帮助我们描述这种选择及其波动。模型给某个续写较高概率，表达的是它对续写的预测，并不等于这段话所述事实为真的概率。

[Softmax](/concepts/softmax/)把分数转换成总和为一的正权重，连接了前面的两部分。在语言生成中，这些数可以作为候选 token 的概率；在注意力中，它们用于组合不同位置的信息。同一种运算承担不同的用途，读公式时需要连同输入和输出的含义一起看。

到这里，后续章节里常见的一段计算就能逐步读懂：输入用向量表示，经过矩阵变换，用点积计算分数，再由 Softmax 得到组合信息的权重。这只是注意力计算的一部分，却已经足以让一串符号对应到几件明确的事。

## 基础知识怎样帮助工程判断

这些知识的用途会体现在很具体的判断中。比较两套检索方案时，需要知道它们如何计算相似度、是否归一化；调整生成参数时，需要观察输出分布怎样变化；阅读模型代码时，需要检查矩阵和向量的维度是否匹配。每一次判断，都比“换个参数试试”多了一点依据。

同时，数学解释也有边界。相似度高的段落仍可能过时，连贯的回答仍可能有事实错误，生成出的工具请求也可能执行失败。向量与概率帮助我们理解这些系统中的局部计算；文档是否可信、任务是否完成，还要检查来源、工具结果与评测证据。后面的模型和 Agent 章节会继续处理这些问题。

## 怎样读这一章

可以先从向量开始，再学习矩阵和点积；概率分布可以独立阅读，之后接着读 Softmax。已经熟悉其中某一部分时，可以直接进入对应章节，看看例子和它与模型的联系，再决定是否需要细读。

第一遍阅读时，不必追求记住所有公式。更有用的目标是：能说清一次运算的输入与输出，能用一个小例子算出结果，并能解释改变输入后结果为什么变化。遇到交互实验，先预测再操作：转动向量时点积会怎样变化，把概率集中到一个结果上又会发生什么。图像与数值不符合预期的地方，通常就是值得回头读的地方。

读完这一章，你应当能把向量、矩阵、分数和概率放在同一个计算过程中理解，并知道哪些结论可以由这些数支持。这些能力会随着后续章节继续加深。现在可以从[向量](/concepts/vector/)开始，把一组坐标变成看得见、算得出的对象。
