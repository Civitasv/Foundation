# 向量

## 摘要

向量既可以描述空间中的位移，也可以承载文本、图像和模型内部的特征。两种用途共享同一套加法、缩放与比较运算，但数值所代表的意义来自不同地方。本章从二维几何出发，说明向量与坐标的区别，推导长度、线性组合和归一化，再比较人工特征、静态词嵌入与上下文表示。重点是理解一组数字怎样成为可运算的表示，以及哪些关于“相似”或“语义”的结论仍需要额外依据。

## 为什么同一句话可以变成一组数字

假设一个知识库要回答“忘记密码怎么办”。文档里可能没有这句原话，只有“重置账户凭据”的说明。逐字匹配容易漏掉它；基于向量的检索则尝试把问题和段落编码成数值表示，再用这些表示之间的关系寻找候选材料。

这里有两件事需要分别理解。向量提供运算的形式：如何相加、缩放、测量距离。编码方法决定内容如何进入这种形式：哪些差异被保留，什么样的文本在计算中显得接近。只要把文字换成数字，并不会自动获得语义检索能力。

同样的区别也出现在语言模型里。嵌入向量、某一层的隐藏状态和用于检索的段落向量都能写成数列，却未必承担同一种任务。学习向量的意义，在于先掌握它们共用的数学结构，随后再根据模型和训练目标解释这些数值。

<Aside kind="context" title="阅读准备">

本章只需要基本四则运算。我们先使用二维、三维的例子；高维表示沿用相同的运算规则。矩阵和点积将在后续章节展开。

</Aside>

## 向量、坐标与基底

### 从位移开始

在平面上，从当前位置向右走 3 个单位，再向上走 2 个单位，这段位移可以记为 `v = [3, 2]`。画图时常把箭尾放在原点，箭头落在 `(3, 2)`。把整支箭平移到别处，只要长度和方向不变，它仍然表示同一段位移。

这也说明了点与向量的联系和区别。点标记位置，位移向量描述位置的变化。选定原点后，可以用从原点指向该点的向量表示其位置，因此二者经常使用同样的坐标。模型里的向量也常被画成空间中的点，以便讨论距离和聚类。

### 坐标依赖我们怎样测量

在标准坐标系中，两根基向量分别是 `e₁ = [1, 0]` 和 `e₂ = [0, 1]`。它们给出了测量所用的方向和单位。于是：

<Equation label="坐标是基向量的组合系数">

**v = 3e₁ + 2e₂**

</Equation>

这里的 3 和 2 是组合系数。如果改用 `b₁ = [2, 0]`、`b₂ = [0, 1]` 作为基底，同一个 v 就写成 `1.5b₁ + 2b₂`，新坐标为 `[1.5, 2]`。位移没有变，变的是描述它的尺子。

在有限维空间里，一组基底需要满足两个条件：能够组合出空间里的每个向量，而且这种表示唯一。前者叫张成，后者由线性无关保证。若两根箭头落在同一直线上，无论怎样伸缩相加，都不能覆盖整个平面。

<Aside kind="definition" title="本章的记号约定">

下文默认使用相互垂直、长度为 1 的标准基底。`[x, y]` 是坐标的简写；需要区分行列时，`[x, y]ᵀ` 表示列向量。一般向量空间还可以由函数等对象组成，本章聚焦模型中常用的实数坐标空间。

</Aside>

基底的区分也给表示学习一个提醒：不能只因为两个模型都输出相同维度，就逐坐标比较它们的表示。它们可能学出了不同的坐标组织；除非经过共同训练或明确对齐，否则这些数值不一定可直接比较。

## 加法与缩放怎样组合信息

两个向量相加，就是把对应坐标相加。取 `u = [3, 2]`、`v = [-1, 1]`，得到 `u + v = [2, 3]`。几何上可以先走 u，再从终点走 v，总位移就是它们的和。这一解释同时说明，加法要求各个坐标具有可对应的含义。

<Equation label="向量加法与标量乘法">

**[x₁, y₁] + [x₂, y₂] = [x₁ + x₂, y₁ + y₂]**

**a[x, y] = [ax, ay]**

</Equation>

标量 a 是一个数。把 `[3, 2]` 乘以 `0.5`，长度减半；乘以 `-1`，方向反转；乘以 `0`，则得到零向量。更一般地，a 会使长度变为原来的 `|a|` 倍。零向量没有确定的方向，这一点在讨论夹角和归一化时尤其重要。

把加法和缩放放在一起，就得到线性组合。对于上面的 u、v，`0.25u + 0.75v = [0, 1.25]`。两个非负系数的和为 1，因此结果落在 u 与 v 的端点之间，是一个加权平均。若允许负系数，或者不要求系数和为 1，线性组合就不再局限于这段线段。

注意力中的加权汇总、一些段落表示的平均，以及残差连接中的相加，都用到了这些基本运算。不过，运算成立不代表解释自动成立。把两个词向量相加，在数学上没有困难；结果是否表达某种有用的语义组合，要看模型是否学到了相应结构。向量的可加性并不保证语言意义也按同样方式相加。

## 长度、距离与归一化

在二维标准坐标系中，向量与两个坐标轴构成直角三角形。由勾股定理可得欧氏长度，也称 L2 范数：

<Equation label="欧氏范数">

**‖v‖₂ = √(x² + y²)**

**‖v‖₂ = √(v₁² + ⋯ + v_d²)**

</Equation>

第二行把相同定义扩展到了 d 维。对于 `[3, 2]`，长度为 `√13 ≈ 3.606`。如果把两个向量看作空间中的点，它们之间的欧氏距离就是差向量的长度。例如 `[3, 2]` 与 `[1, 1]` 的差为 `[2, 1]`，距离为 `√5`。

长度是否有可解释的业务含义，取决于表示方式。若坐标分别是身高与体重，直接平方相加会混合不同单位；把身高从米改成厘米，结果还会大幅改变。此时，需要先决定特征尺度和比较目标。即使坐标由模型学习，也不能未经验证就把较长的向量解释成“更重要”或“更有把握”。

有时比较更关心方向。这时可以对非零向量进行 L2 归一化：

<Equation label="把非零向量缩放到单位长度">

**v̂ = v / ‖v‖₂**

</Equation>

`[3, 2]` 归一化后约为 `[0.832, 0.555]`。它保留方向，却不再保留原来的长度；`[6, 4]` 会得到同样的结果。因此，归一化是一项有取舍的处理。它适合那些希望忽略长度差异的比较，而不是所有任务的默认改进。[点积](/concepts/dot-product/)一章会解释，归一化后如何通过点积比较方向。

<Aside kind="tip" title="更换基底后，长度公式也要跟着检查">

前面的同一段位移在新基底下坐标为 `[1.5, 2]`，不能直接据此算出长度 `2.5`：新基底的第一根向量长度是 2。标准坐标下的平方和公式依赖正交单位基底；换成一般基底后，需要把基向量之间的长度和夹角关系计入计算。

</Aside>

## 从人工特征到上下文表示

### 表示中的关系从哪里来

一种简单的文本表示是为词表中的每个词分配一个坐标，记录词频。这种表示容易解释，却不自动表达近义关系。若把单个词表示成独热向量，即只有对应位置为 1，其余为 0，那么任意两个不同词的欧氏距离都是 `√2`。“猫”和“狗”不会因为含义相关而比“猫”和“合同”更近。

神经语言模型尝试从数据中学习这种关系。Bengio 等人的工作把词表示与语言预测联合训练，使不同上下文可以通过共享表示交换统计信息；Mikolov 等人的研究进一步探索了高效学习连续词表示的方法，并用词语关系任务评估它们。[Bengio 等，2003](https://www.jmlr.org/papers/v3/bengio03a.html)，[Mikolov 等，2013](https://arxiv.org/abs/1301.3781)。

这些工作中的相近关系来自训练，而不是“使用向量”这一形式本身。模型可能让某些替换关系、主题关系或语法关系变得容易识别，也可能保留数据中的偏差。逐维解释通常不够可靠，有用的信息可以分布在多个坐标上。

### 一个词的表示与它在句中的表示

静态词嵌入通常为同一个词提供固定向量，但同一个词在不同句子里承担的含义可能不同。例如英文 bank 可以出现在银行业务或河岸的描述中。上下文模型会结合周围文本形成内部表示。BERT 的研究以双向上下文预训练展示了这一类表示的使用方式。[Devlin 等，2018/2019](https://arxiv.org/abs/1810.04805)。

因此，读模型论文时，看到“向量”还要继续追问：它是输入嵌入、某一层的上下文状态，还是把整段文本汇总后的表示？三者可以具有相同的维度，但信息来源和训练用途不同。一个适合预测后续 token 的隐藏状态，也未必可以直接当作高质量的检索向量。

<Aside kind="source" title="二维图能够说明什么">

本章实验说明坐标、长度和缩放的关系。真实嵌入的二维可视化还需要降维，不能假定图上所有距离都忠实保留了原空间的关系。高维中的加法和范数仍有精确定义，二维图则只展示我们选择保留的一部分信息。

</Aside>

## 最小实现与可核对的结果

下面的代码把二维坐标放进一个对象。`add` 与 `scale` 逐分量实现前面的定义，`magnitude` 使用 `Math.hypot` 计算欧氏长度。

<CodeStep title="vec2.ts">

~~~ts
type Vec2 = {
  x: number;
  y: number;
};

function add(a: Vec2, b: Vec2): Vec2 {
  return {
    x: a.x + b.x,
    y: a.y + b.y
  };
}

function scale(v: Vec2, scalar: number): Vec2 {
  return {
    x: v.x * scalar,
    y: v.y * scalar
  };
}

function magnitude(v: Vec2): number {
  return Math.hypot(v.x, v.y);
}
~~~

</CodeStep>

对 `u = { x: 3, y: 2 }` 和 `v = { x: -1, y: 1 }`，`add(u, v)` 应得到 `{ x: 2, y: 3 }`；`scale(u, 0.5)` 应得到 `{ x: 1.5, y: 1 }`；`magnitude(u)` 则约为 `3.606`。这些结果可以与正文和实验逐项对照。

这里假定输入坐标是有限实数。若进一步编写归一化函数，就必须单独处理长度为零的情况，不能直接除以零。推广到数组表示的高维向量时，还要检查两个输入是否等长。维度相同保证运算在形式上可做；表示是否来自兼容的模型与坐标约定，则是调用方需要保证的另一项条件。

## 讨论：向量能帮助我们判断到哪一步

在基于向量的检索中，编码模型和比较方式共同决定候选结果。更换嵌入模型后，即使输出维度不变，也需要重新确认查询和文档表示是否兼容；改变归一化方式后，长度在排序中的作用也会变化。这些选择都应通过实际检索任务检验。

在 Transformer 中，隐藏表示会经过变换与加权组合，并通过残差路径相加。向量运算使这些过程可以精确描述，但单个坐标或一次相似度计算通常不足以解释模型的全部判断。[Vaswani 等，2017](https://arxiv.org/abs/1706.03762)。对于 Agent，检索到内容相关的段落只是获得了候选证据，仍需检查来源、时效和是否真正支持回答。

本章建立的是表示与运算之间的联系：坐标依赖约定，长度与方向提供不同信息，加法与缩放允许组合表示。接下来，[矩阵](/concepts/matrix/)把这些表示组织成可学习的变换，[点积](/concepts/dot-product/)则进一步讨论比较。带着“这些数字来自哪里、运算保留了什么”的问题继续阅读，会比把每个向量都称为“语义”更有帮助。
